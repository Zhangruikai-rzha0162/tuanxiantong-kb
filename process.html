保全全流程图解

一笔在线保全从发起到办结的完整路径，标注每个环节调用的接口（编号对应需求规格说明书 4.3 节）：

选择保单与保全项目 团险通
经办人选定团单与 NI / ZT / IR 保全项 → 调用 保全是否受理接口（4.3.5） 做前置校验：挂起状态、未核销应收、保单终止、回执签收、生效日期、无名单保单、建工险限制等。不通过则即时提示，客户体验前置保障。
下载模板、填写并上传人员清单 团险通
团险通先做轻量校验，再调用 被保险人清单提交接口（4.3.6） 将清单传入核心。核心落库后由清单校验批处理执行全量校验。
查看校验结果 团险通
校验完成后，核心通过通知批处理回传：通过与不通过的被保人名单、不通过原因；对通过者生成补退费明细与合计金额、收费账户信息、客户经理手机号。业务进度："校验完成待确认"。
点击"确认申请" 团险通
调用 保全申请确认接口（4.3.7）。核心复核受理条件 → 保单挂起 → 生成保全受理工作流并自动申请确认 → 申请书 / 告知书 / 名单图片归档为 604 影像件 → 对校验通过人员生成收付费信息。
核保与审批 核心 / 运营
自动核保，不通过转人工。需补充资料时运营人员下发核保补充资料问题件，客户在团险通上传资料（核保资料补充接口 4.3.9），核心归档 615 单证并自动核销问题件，业务进度"3-人工审核中"。核保拒绝 / 审批拒绝 / 撤销 / 强制终止 → 业务进度"9-保全终止"。
收付费 核心
审批通过后：收费件 → 生成交费通知书（自动打印）、业务进度"4-待交费"、短信提醒；退费件 → 银行代付，失败则生成转账不成功通知书与问题件，客户在团险通修改银行信息后调用 转账不成功处理接口（4.3.8） 完成回销与重新付费。
保全生效，批单生成 核心
收付费完成 → 确认生效（业务进度"8-确认生效"）→ 核心自动调用打印服务生成批单 → 短信通知经办人与客户经理。
客户下载批单 / 通知书 团险通
调用 通知书批单下载接口（4.3.11）：已打印则返回文件链接；未打印且当日调用打印次数 < 2 则自动触发打印。批单未生效不可下载。
保单解挂，流程结束 核心
保全办结后解除挂起，保单恢复可办理状态。
异常分支：申请确认前客户可在团险通删除保全（保全删除接口 4.3.10），核心删除清单与补退费数据；已申请确认的保全不允许删除，只能由核心侧撤销 / 终止。

十二个接口

编号接口方向一句话说明
4.3.1保单列表查询团险通 → 核心按登录手机号查询其作为联系人的全部团单（支持按保单号 / 状态过滤）
4.3.2保单详情查询团险通 → 核心返回基本信息、投保单位、银行账户、纳税人信息
4.3.3保险方案查询团险通 → 核心返回方案及险种明细（免赔、赔付比例、保额、保费等）
4.3.4被保人清单查询团险通 → 核心分页查询保单被保人名单及状态
4.3.5保全是否受理团险通 → 核心入口闸门：校验挂起、未核销应收、终止、回执、生效日、无名单、建工险等
4.3.6被保险人清单提交团险通 → 核心提交增 / 减 / 换人清单，核心落库并触发批处理校验
4.3.7保全申请确认团险通 → 核心发令枪：复核受理 → 挂起 → 生成工作流 → 影像归档 → 生成收付费
4.3.8转账不成功处理团险通 → 核心更新银行信息、回销通知书、问题件置已处理、反馈业务进度
4.3.9核保资料补充团险通 → 核心上传健康告知书等，归档 615 单证，问题件置已处理
4.3.10保全删除团险通 → 核心删除未确认的保全数据（清单 + 补退费）
4.3.11通知书批单下载团险通 → 核心终点交付：下载交费 / 转账不成功通知书、批单、定期结算 / 月交通知书
4.3.12清单校验字段查询团险通 → 核心返回生效 / 终止日期、是否月交、方案是否月薪 / 费率型，支撑前端校验
共性规则：所有接口均要求手机号必传，且与核心留存的投保单位联系人手机号一致，否则返回业务异常"保单投保单位联系人手机号与登录手机号不匹配"——这是线上身份认证的核心机制。

接口调用链

申请阶段
4.3.5 能不能做？→ 4.3.6 数据给你→ 4.3.7 正式开始
处理阶段
核心：核保 / 审批 / 收付费→ 4.3.9 补资料（可选） 4.3.8 转账失败（异常）
交付阶段
确认生效 · 批单生成→ 4.3.11 做完了，给客户

查询类接口（4.3.1–4.3.4、4.3.12）贯穿全程，支撑页面展示与前端校验；保全删除（4.3.10）仅在确认前可用。

批处理机制

核心新增两个批处理，运行频次均为 2 分钟一次；处理或通知失败、接口超时未返回的，下一次运行继续处理，直至成功：

批处理职责
清单校验批处理对团险通上传的人员清单执行全量校验（规则见 4.2 / 本库规则页）
通知批处理五类通知：清单校验完成、核保补充资料问题件、转账不成功、定期结算 / 月交、保全状态变更
已知短板：批处理回传导致前端流程分段（客户需二次登录确认）。2026 优化方向为改实时处理、取消分段。详见系统架构 · 后续优化方向。

进度码含义触发条件

—问题件待处理下发核保补充资料问题件 / 转账不成功问题件

短信通知

五类短信均为单次发送（失败不重发），接收人为团单联系人手机号 + 承保地客户经理手机号（多位客户经理取分佣比例最高者，并列取代码最靠前）：

短信发送条件
核保补充资料问题件待处理团险通渠道保全下发核保补充资料问题件时
转账不成功问题件待处理付费转账不成功下发问题件时
保全交费提醒保全产生收费且审批通过时（含交费截止日期）
定期结算 / 月交交费提醒定期结算审批通过且金额为正；或月交抽档成功且金额为正
保全案件生效通知保全状态更新为"确认生效"时（含人数与涉及费用）
